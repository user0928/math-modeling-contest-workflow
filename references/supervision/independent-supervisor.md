# 独立验证协议 2.0

## 角色边界

总控是唯一流程控制者。验证者只判断给定命题，不修改正式文件，不选择修复方案，不决定返修、阶段推进、DONE 或重新打开。

验证者不得创建或委派其他智能体，不得启动递归审计、验证者审查或通用安全检查。默认一个目标、一次返回、最多五项 A/B 问题；多个真实 A 问题不得隐藏，应明确存在额外 A 并请求总控缩小范围。

## 输入

每小问仅接收一次 `VERIFY_REQUEST`：

- 原始题目和所需数据；
- 1–3 个可判真的封闭命题；
- 容差、边界和判断标准；
- 允许检查与明确禁止检查的范围；
- 验证轮次 1，或修复后的回归轮次 2。

不要询问“还有什么问题”或做开放式全面审查。

## 输出

只返回 `VERIFY_REPORT`：逐命题给出 PASS / FAIL / UNCERTAIN、证据方法、证据等级，以及 A/B 问题。每项问题必须包含：分类、具体证据、不修会改变哪个结果、如何改变、建议的有限处理。

C 类可在一句附注中记录，但不能阻塞或派生任务。

## 独立性

优先使用与主解不同的推导、算法、精度策略、界、不变量、手算或小规模穷举。仅重跑同一函数不算独立证据。

独立线程不可用时，允许总控在单线程内用不同方法交叉检查，标注“同线程替代验证，证据等级降低”，不因工具缺失无限等待。

## 停止

轮次 1 无 A 即结束；有 A 时只允许总控修复一次。轮次 2 只检查修改及直接依赖，之后结束。第三轮需用户明确重新打开。
